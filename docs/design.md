# Arena 设计摘要

Arena 采用“本地 Python 服务 + 无构建步骤的浏览器前端”。人工动作和策略动作都进入同一个确定性规则引擎；前端只展示服务返回的公开状态，不自行计算正式结果。

## 核心规则

- 20 个频道，每局随机 10–16 个源，频道不重复；地图由随机种子复现。
- 源位于距原点不超过 1800 m 的圆内，接收半径为 1000–1500 m。
- 移动速度 5 m/s；检测 5 s；实际换频加 1 s；清除成功 5 s、失败 3 s。
- 5 m 内返回近距离信息，20 m 内清除成功，示向误差固定在 ±1° 且可复现。
- 混合模式按 `6/16` 抽取定向源，若没有定向源则重新抽取。

## 状态与隐私边界

隐藏地图只保存在 Python 会话文件。正式 API 默认不返回源真值、总数、接收半径、源类型或方向。功能展示会返回真值给浏览器，但策略控制器会再次过滤，确保策略只获得玩家公开信息。

每个玩家命令执行前保存快照；撤销恢复公开游戏状态和虚拟时间，但玩家现实时间不回退，并永久标记辅助。批量检测共用一个命令 ID，因此作为一个整体撤销。

## 回放和排行榜

回放只保存模式、种子、源数、正式动作和期望结果，不保存源坐标或方向。规范 JSON 的 SHA-256 用于发现传输中的修改；验证器重新生成地图、重放动作并核对虚拟时间、清除数和完成状态。

排行榜按人工/策略和两种正式地图组成四类，但呈现在同一个页面。它比较随机单局的虚拟秒/源，并按 GitHub 用户每类保留最低值。成绩以 PR 进入仓库；可信主分支验证器只读取候选 JSON，不执行 PR 中的代码。合并后 GitHub Pages 自动重建。
